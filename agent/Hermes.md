
# 核心概念：会自我学习、自我进化的本地AI助手

## 本地（local）

你的对话记录、生成的文件、积累的记忆，全部存储在你的本地磁盘上

## 自主（Autonomous）

传统的AI工具是被动的，你让它做什么，它才做什么。Hermes是主动的，你给一个目标，它会自己规划步骤、调用工具、处理异常、调整策略，直到目标达成。

## 学习（learning）

Hermes有一个核心的自学习闭环。每次交互结束后，系统会分析：
- 这次任务完成的怎么样？
- 用户的反馈是什么？
- 有哪些经验可以沉淀下来？
- 有没有新的模式需要记录？
这些分析结果会被存入到记忆系统，成为Hermes的“经验”。下次遇到类似情况，它会基于这些经验做出更好的决策。

## 进化（Evolution）

学习是积累知识，进化是升级能力。Hermes的技能系统支持自我进化：

- 它能根据你的使用模式，自动创建技能
- 它能分析技能的使用效果，自动优化技能的实现
- 它能从社区共享的技能库学习，吸收最佳实践

# 五大核心优势

## 优势一：记忆自动归档

三层记忆系统：

### 第一层：会话记忆（短期上下文）

一次会话的上下文

### 第二层：持久记忆（长期知识库）

利用SQLite数据库搭配FTS5全文检索引擎， Hermess可以把所有重要的信息长期保存下来。

### 第三层：Skill级记忆（跨会话知识沉淀）

这是Hermes的独创。当你在多个会话中返回处理某类任务时， Hermes会自动提炼出“通用模式”，形成Skill级别的记忆。这些记忆不仅服务于当前会话，还会被用于优化技能本身。

## 优势二：自主创建Skill

传统 Agent 框架的技能系统是"静态"的——开发者写好技能代码，用户拿来用。如果用户需要一个框架里没有的技能，就得等开发者更新，或者自己写代码。

Hermes 打破了这种模式。它具备**自动技能创建**的能力：

当你反复执行一类任务时，Hermes 会识别出这个模式。比如，你每周都要"收集竞品动态、整理成周报、发送给团队[]()"。做了几周之后，Hermes 会主动问你："我发现你每周都在做类似的任务，是否需要我创建一个自动化的技能？"

如果你同意，Hermes 会自动：
1. 分析这个任务的步骤和依赖
2. 生成对应的 Skill 代码
3. 注册到技能库中
4. 下次你需要的时候，一键执行

更厉害的是，这个 Skill 不是一成不变的。随着你使用的次数增多，Hermes 会不断优化它——简化步骤、修正错误、增加新的功能。

> **Tips**
>
> 自动创建 Skill 的功能默认是开启的，但你可以在配置中关闭它，或者设置触发阈值（比如"至少重复 3 次才提示创建"）。对于喜欢手动控制一切的高级用户，这些选项给你了充分的自由度。

## 优势三：技能自我进化

不仅新技能可以自动创建，现有的技能也会自我进化。

Hermes 有一个内置的**技能评估和优化循环**：

1. **执行监控**：每次技能执行时，系统会记录执行时间、成功率、用户反馈等指标。
2. **效果分析**：定期（默认每周）分析技能的使用数据，找出效率瓶颈和常见失败点。
3. **自动优化**：基于分析结果，尝试改进技能的实现。比如，把串行执行的步骤改为并行，或者增加错误处理的逻辑。
4. **A/B 测试**：新版本的技能不会直接替换旧版本，而是先在小部分场景中试用，确认效果更好后才全面推广。
5. **用户确认**：对于重大变更，Hermes 会征求你的同意。对于细微优化，它可以自动应用。

这个过程就像是你的助理不仅在做事情，还在"琢磨怎么把事情做得更好"。

> **常见问题**
>
> **Q：技能自我进化会不会把我的技能改坏？**
>
> **A：** 不会。Hermes 采用了多重保护机制。首先，所有优化都会先创建新版本，原版本会被保留。其次，新版本会经过 A/B 测试验证。第三，你可以随时回滚到旧版本。第四，你可以设置某些技能为"锁定"状态，禁止自动优化。安全性是设计的第一优先级。


## 优势四：按需检索

大语言模型有一个固有的限制：**上下文窗口有限**。即使是最先进的模型，也只能同时处理几十万字的上下文。如果 Agent 把所有历史记忆都塞进上下文，很快就会爆表。

Hermes 的解决方案是**按需检索（Retrieval on Demand）**：

当接收到一个新任务时，Hermes 会先进行"需求分析"：这个任务需要什么知识？需要哪些历史背景？需要调用什么技能？然后，它只去检索相关的记忆片段，把不相关的信息过滤掉。

这就好比一个优秀的律师在接案子时，不会把律所所有的卷宗都翻一遍，而是根据案情快速定位到相关的判例和法规。

按需检索的核心技术是**语义检索 + 关键词检索的混合方案**：

- **语义检索**：利用向量嵌入技术，找到"意思相近"的内容。比如，你问"上次谈的那个合作"，即使你没有用"合作"这个词，系统也能根据语义理解找到相关内容。
- **关键词检索**：利用 FTS5 全文检索，快速定位包含特定关键词的内容。
- **混合排序**：把两种检索的结果合并，按相关度排序，选出最相关的片段送入上下文。
## 优势五：用户建模

这是 Hermes 最具前瞻性的设计之一。

每个用户都是独特的。你的说话方式、工作习惯、知识背景、审美偏好，都和别人不一样。一个真正智能的 Agent，应该能"认识"你，并且根据你的特点来调整自己的行为。

Hermes 的**用户建模系统**会为你建立一个多维度的画像：

**基础画像**：你的角色（开发者/产品经理/投研人员等）、技术栈偏好、常用工具、工作时间规律等。

**交互偏好**：你喜欢简洁的回答还是详细的解释？你喜欢代码示例还是文字描述？你喜欢直接给答案还是引导你自己思考？

**知识图谱**：你熟悉哪些领域？在哪些领域你是新手？你经常提及的人物、公司、概念之间的关系是什么？

**任务模式**：你经常做什么类型的事情？你的任务有什么规律？（比如"每周一上午看周报"、"每天下午 3 点查数据"）

**反馈历史**：你对 Agent 的哪些回答满意？哪些不满意？你的修改习惯是什么？

基于这个画像，Hermes 会动态调整它的行为：
- 给开发者的回答会包含更多技术细节和代码示例
- 给产品经理的回答会更多关注用户场景和业务价值
- 如果你是个急性子，它会优先给出结论，细节放在后面
- 如果你是个谨慎的人，它会给出更多选项和权衡分析

> **Tips**
>
> 用户建模是完全本地化的，你的画像数据只存储在你自己的机器上。Hermes 承诺不会上传任何用户画像数据到第三方服务器。这也是选择本地 Agent 的重要理由之一。

# 四层温度记忆模型
## 热记忆（即时）—— 当前会话上下文

热记忆是最「热」的记忆，就像你大脑中正在思考的内容一样，访问速度最快，但容量最小，而且会随着会话结束而消失。

在 Hermes 中，热记忆就是当前会话的上下文窗口。它包含了：

- 当前对话中你和 Agent 的所有消息
- 最近一次工具调用的结果
- 系统提示（System Prompt）和 SOUL.md 的内容
- 当前激活的 Skill 的上下文

热记忆的特点可以用三个词概括：**快、小、暂存**。

- **快**：所有数据都在内存中，访问延迟几乎为零
- **小**：受限于大模型的上下文窗口（通常是 4K-200K Tokens）
- **暂存**：会话结束或 /compact 执行后，部分内容会被压缩或丢弃

###  温记忆（持久）—— MEMORY.md + USER.md

温记忆就像你写在便利贴上的重要提醒，或者是你手机备忘录里的关键信息。它们不像热记忆那样随时在眼前，但比翻查旧笔记本要快得多。

Hermes 的温记忆由两个核心文件组成：

**MEMORY.md**：存储与任务相关的持久化信息。比如：

- 「用户要求所有 Python 代码都使用 Type Hints」
- 「当前项目的 Git 仓库地址是 https://github.com/user/project」
- 「上次分析的那只股票代码是 600519」

**USER.md**：存储用户画像和行为模式。比如：

- 「用户喜欢用中文交流，但技术术语保留英文」
- 「用户在上午 9-11 点效率最高，适合安排复杂任务」
- 「用户对深度学习话题感兴趣，对区块链话题不感兴趣」

这两个文件都是纯文本的 Markdown 格式，存储在 Hermes 的配置目录中。它们的容量被严格限制（MEMORY.md 约 2200 字符，USER.md 约 1375 字符），这是经过精心设计的——如果文件太大，每次加载都会消耗大量 Token；如果太小，又无法记录足够有用的信息。

##  冷记忆（检索）—— SQLite + FTS5 + LLM 摘要

冷记忆就像你书架上排列整齐的档案柜，或者是电脑里分门别类的文件夹。里面存储了海量的历史信息，但你不会一次性把它们全部搬到桌面上，而是需要时去查找。

Hermes 的冷记忆系统由三个核心组件构成：

**SQLite 数据库**：轻量级的本地关系型数据库，存储所有的历史对话、工具调用结果、文件操作记录等。一个 SQLite 文件就是一个完整的数据库，不需要单独的服务进程。

**FTS5 全文索引**：SQLite 内置的全文搜索引擎。你可以把它理解为一个小型的「本地 Google」——输入关键词，它能瞬间从海量文本中找到包含这些词的记录。

**LLM 摘要**：利用大语言模型的能力，自动为每次会话生成简明扼要的摘要。这些摘要也会被索引到 FTS5 中，让你在搜索时能更快地定位到相关会话。

冷记忆的核心设计思想是「按需检索」。当你开启一个新会话时，Hermes 不会把过去一年的所有对话都加载到上下文中，而是：

1. 分析你当前输入的内容，提取关键词
2. 用 FTS5 在历史记录中检索相关片段
3. 只把最相关的几条记录（通常 3-5 条）提取出来
4. 将这些相关片段注入到当前上下文中

这种方式让 Agent 拥有了「回想」能力，同时又不会因为记忆太多而「大脑过载」。

### 外部记忆（扩展）—— Honcho、Mem0 等

外部记忆是四层模型的最外层，相当于你的个人图书馆、云端笔记、或者是请了一位专门帮你整理资料的研究助理。它们不是 Hermes 内置的，但可以通过插件或 API 无缝集成。

目前支持的外部记忆方案包括：

- **Honcho**：专门用于推导用户行为模式的记忆模块
- **Mem0**：强大的记忆管理平台，支持向量检索
- **OpenViking**：面向企业级场景的记忆扩展
- 以及更多社区开发的记忆插件

外部记忆的优势在于专业化和扩展性。比如 Honcho 在用户行为建模方面比 Hermes 内置的 USER.md 更深入；Mem0 在跨设备同步方面有独到之处。但它们的缺点是需要额外配置，且部分服务涉及数据外传。
